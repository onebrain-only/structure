Flutter web build, driven with this session's `mcp__claude-in-chrome__*` tools. Walks
each flow the way a real user would and reports what happened against what was
supposed to happen.

**No database access at all** — not even read (`CONTRACT.md` §3). **No code-write
access.** Output is Jira bugs and comments with reproduction steps; it does not fix
what it finds. In this repo it writes this file and its own memory directory, nothing
else.

- `flutter test test/app/route_inventory_test.dart` with `.env` absent → **exit 0**,
  3/3 pass.
- `flutter test` (bare — the actual `ci.yml:39` step) with `.env` absent → **exit 0**,

`.env` restored; `git status --porcelain` after every run shows only `?? test/app/`
— the executor's two untracked files, nothing else.

**2. The golden tells the truth.** The golden was generated by the same walker that
reads it, so a walker bug would produce a self-consistent golden that passes forever.
Broke the circle by resolving 8 entries by hand against `lib/app/app_router.dart` and
`lib/utils/constants/route_constants.dart` — including two child routes with joined
parent paths and all four `StatefulShellBranch` rows. **8/8 match, 0 mismatches.**
Independent corroboration of the count: `grep -c "GoRoute("` over the `_routes` list
body (lines 445–1678) = **85**, matching the golden's 85 `GoRoute` rows and the
assertion at `route_inventory_test.dart:116`. 90 golden lines = 85 + 1 shell + 4
branches.

**3. What it catches.** The load-bearing assertion is
`expect(actual, orderedEquals(expected))` at `route_inventory_test.dart:107`, over rows
serialised as `fullPath \t name \t runtimeType` (`:39`). Caught: route deleted, route
added, two routes swapped, `path` changed, `name` changed, and reparenting whenever the
resolved full path or the depth-first position changes. **Missed: a builder swapped
while `path` and `name` are kept** — `toLine()` never reads the builder, so P0-2 could
point a route at the wrong screen and this test stays green.

**Two blind spots worth knowing before the split, neither a defect in the ticket:**

- **Reparenting is only caught indirectly.** A route with an *absolute* path moved from
  last-child of a parent to sibling immediately after that parent produces an identical
  full path *and* an identical DFS position — no row changes, test stays green. Every
  reparent that changes either the joined path or the ordinal position is caught; that
  one shape is not.
- **`.indexedStack` is not actually asserted.** `runtimeType.toString()` on the
  factory's product yields `StatefulShellRoute` (golden line 21), and
  `whereType<StatefulShellRoute>()` at `:120` matches any `StatefulShellRoute`. Swapping
  `.indexedStack` for a custom `navigatorContainerBuilder` passes the test whose name
  says otherwise. Structural only — 1 shell, 4 branches is genuinely asserted.

Neither redirects nor `parentNavigatorKey` are captured either. Scope is the *declared*
table, which is the right scope for a split net — it is not route coverage.

**4. Wired into the gate — YES, no workflow change needed.** `ci.yml:39` runs bare
`flutter test`, which discovers everything under `test/`; the new file is picked up with
no edit to the workflow. `ci.yml:36` is the analyze gate. Both trigger on push to
`Canary` and on PR into `main` (`ci.yml:4-9`).

**Verdict:** the test does guard P0-2 through P0-4 against the failure modes that split
actually produces — dropped, renamed, reordered and repathed routes. It does **not**
guard against a builder rewired behind an unchanged path/name, and that is the one thing
a reviewer must still read the diff for.

**Not verified by this seat:** criterion 5's mid-edit failing run (cannot edit
`app_router.dart`); whether any of the 85 routes actually *resolves* to a working screen
— nothing was navigated and no widget was built; the CI runner itself (measured a local

No ticket transitioned, no bug filed, nothing committed or pushed — reported to
